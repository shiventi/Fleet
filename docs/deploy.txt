Loads settings, builds local tar bundles, and checks received bytes.
The package command builds a bundle locally. It does not upload files, install
dependencies, or start an app.

## DeploySpec

workload holds the existing app settings. files lists paths to include,
relative to the folder containing the manifest. Only listed files are checked;
directories are not scanned or copied. Review the list to keep secrets out.

## DeploySpec::validate

Checks the workload settings and rejects an empty file list or duplicate paths.
Equivalent paths such as assets/data.txt and assets/./data.txt count as duplicates.
Allows at most 256 listed files.

## DeploySpec::load_manifest

Reads JSON, checks the settings, then checks each listed file using the manifest's folder.
A bare filename uses the current folder. Read and parse errors include the manifest path.
Loading does not run the app or change any source files.

## DeploySpec::validate_files

Resolves the supplied root folder. Listed paths must be nonempty and contain only
normal path components: no absolute paths, parent traversal, or leading dot component.
Checks every component for symlinks, including parent folders and dangling links.
The final entry must be a regular file; missing files, directories, sockets, and
pipes are rejected. Nested regular files are allowed.

These are preflight checks, not a secure file reader. Packaging uses open_source
to reject symlinks again while opening each component.

## package

Writes fleet.json with the serialized settings, then each listed file under app/.
Streams file contents to a temporary tar file in the output folder.
Finishes and syncs the file before saving it without replacing an existing output.
Errors drop the temporary file. Source files are not changed or run.
The output folder must already exist.
Checks each opened source's size before copying: at most 25 MiB per file and
100 MiB combined. These counts exclude the manifest and tar headers.

## bundle_info

Reads a regular file in 8 KiB chunks and returns its byte count and lowercase
SHA-256 hash. Rejects non-files and files above 128 MiB; the final path component
cannot be a symlink.
An empty file has a valid hash, but receive_bundle rejects empty uploads.
Does not check tar entries or freeze the file. Keep it unchanged before sending.

## receive_bundle

Reads exactly the announced bytes into a private temporary file in an existing,
agent-controlled folder. Requires a size from 1 byte to 128 MiB and a 64-character
lowercase hexadecimal hash. Uses an 8 KiB buffer; later bytes stay unread.
Rejects early EOF, read errors, and hash mismatches. Saves as `<hash>.tar`
only after checking and syncing the file, without replacing existing files or
symlinks. Errors remove the temporary file.

This helper is not connected to a client command or agent request yet. It does
not check tar entries, extract files, or start apps. Its caller must provide
authentication, read deadlines, and storage limits before accepting network data.
The destination folder must not be writable by untrusted users.

## open_source

Opens each path component relative to an open folder handle, rejecting symlinks
and non-normal components. Intermediate entries must be directories; the last
must be a regular file. Nonblocking opens avoid waiting on a substituted pipe.
File handles stay tied to opened entries even if their paths are later replaced.
This does not freeze file contents: keep source files stable during packaging.

Network uploads, tar validation, and installation are still to be built.

## Example

examples/hello/fleet.json lists app.py and the command python3 -u app.py.
The Python demo prints a count every second. Tests load the manifest without
running Python. Run the deployment tests with cargo test --locked deploy::tests.
