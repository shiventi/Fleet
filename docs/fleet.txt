# Fleet Developer Notes

This text file contains the module and API explanations kept outside the source.
Rustdoc includes it on the documentation home page; source files keep only code,
CLI help settings, and ordinary comments where useful.

The README contains setup and usage instructions. Each agent still manages one app;
multi-app manifest parsing and app state are preparation, not a live multi-app feature.

## src/agent/tests.rs

### TestWorkload

Makes sure tests reap every child, even if an assertion fails.

## src/agent.rs

### Module overview

Manages workload copies and handles commands over mutual TLS.

### ManagedWorkload

Keeps one app's settings, processes, and launch retry time together.

### ManagedWorkload::new

Creates app state without starting processes. The caller validates the spec.

### ManagedWorkload::tick

Checks processes once and adds or removes copies to match this app's target.
Failed launches wait five seconds before retrying; shutdown stops actions.
Does not sleep or handle network requests.

#### Panics
Panics if a process cannot be checked or stopped, or its count exceeds u32.

### ManagedWorkload::status

Returns this app's target and current process count.

### ManagedWorkload::stop

Sets the target to zero, stops this app's processes, and returns its status.

### ManagedWorkload::scale

Changes this app's target. The next tick adjusts its processes.

#### Errors
Rejects counts above the limit without changing the target.

### allow_connection

Runs an agent using trusted client certificates and a shared token.

#### Errors
Returns an error if TLS setup or agent startup fails.

#### Panics
Panics if a process cannot be checked or stopped, or its count exceeds u32.

### allow_device_connection

Runs an agent using approved client device keys and a shared token.
Approvals are copied at startup; restart the agent after changing them.

#### Errors
Returns an error if device-key setup or agent startup fails.

#### Panics
Panics if a process cannot be checked or stopped, or its count exceeds u32.

### serve

Adds or removes copies and handles commands using the supplied TLS config.

Ctrl+C ends the loop and stops direct child processes.
Failed launches are logged and retried after at least five seconds.
The agent keeps handling commands during this delay.
Client I/O can delay checks for up to five seconds per connection.
Reads `FLEET_TOKEN` once at startup and checks it before handling any command.
Requires an authenticated TLS client. Remote addresses need `allow_remote`.
Wildcard addresses such as `0.0.0.0` and `::` are rejected.

#### Errors
Returns an error if `FLEET_TOKEN` is missing, blank, or not valid text,
or the listener or Ctrl+C handler cannot be set up.
Later connection errors are logged and the loop continues.

#### Panics
Panics if a process cannot be checked or stopped, or its count exceeds u32.

### send_reply

Sends one JSON reply followed by a newline.

#### Errors
Returns an error if encoding or writing fails.

### handle_client

Checks the request's token before handling its command.

#### Errors
Returns an error if reading, writing, or encoding fails.
Invalid requests or wrong tokens receive an error reply without changing the workload.

## src/client.rs

### Module overview

Sends JSON commands over mutual TLS and prints the agent's replies.

Each client loads `FLEET_TOKEN` and its TLS config once. The token must match the agent's.
TLS verifies the remote identity before any command or token is sent.

### status

Gets the agent's status and prints its name and copy counts.

#### Errors
Returns an error if fetching the status fails.

### FleetClient

Holds a token and TLS config for repeated requests, including across threads.
Each request opens a new connection. Create a new client to reload credentials.

### FleetClient::new

Loads the token and TLS files without connecting to an agent.

#### Errors
Returns an error if the token is missing or blank, or the TLS files cannot be loaded.

### FleetClient::fetch_status

Gets the agent's status without printing it.

#### Errors
Returns an error if connecting, sending, reading, or parsing fails,
or the agent rejects the request.

### FleetClient::stop

Asks the agent to stop its workload and prints the updated counts.

The agent stays running and the manifest file is unchanged.

#### Errors
Returns an error if connecting, sending, reading, or parsing fails,
or the agent rejects the request.

### FleetClient::scale

Sets the desired copy count and returns the agent's current counts without printing.
The running count may take another agent loop to reach the target.

#### Errors
Returns an error if connecting, sending, reading, or parsing fails,
or the agent rejects the request.

### FleetClient::from_config

Loads the shared token and stores the supplied TLS config.

### FleetClient::new_device

Loads a client using our device key and the selected server's approved key.

#### Errors
Returns an error if the token is missing or blank, or the keys cannot be loaded.

### FleetClient::for_peer

Loads our identity, the named approved server, and the shared token.

#### Errors
Returns an error if loading fails, the peer is unknown, or the token is invalid.

### fetch_status

Loads a client and gets one agent's status without printing it.

#### Errors
Returns an error if client setup or the status request fails.

### stop

Loads a client, stops the workload, and prints the updated counts.

#### Errors
Returns an error if client setup or the stop request fails.

### scale

Loads a client, sets the desired copy count, and prints the current counts.

#### Errors
Returns an error if client setup or the scale request fails.

## src/controller.rs

### Module overview

Checks the status of agents listed in a cluster file.

### NodeSpec

One agent to check.

### NodeSpec::name

A label shown in the watcher output.

### NodeSpec::address

The agent's numeric IP address and port.

### NodeSpec::server_name

The name expected in the agent's certificate.

### NodeSpec::peer

Saved device name used by device-key connections; optional in certificate mode.

### ClusterSpec

The agents listed in a cluster file.

### ClusterSpec::nodes

Agents checked during each round.

### watch

Checks agents in batches of up to four and pauses two seconds after each round.

Failed checks are printed without ending the loop. Each batch runs its checks
together and finishes before the next batch starts. Ctrl+C ends this watcher,
not the agents or their workloads.
One client shares the loaded token and TLS config across all checks.
Restart the watcher to load changed credentials. Each check opens a new connection.
This function does not start, stop, or move workloads.

#### Errors
Returns an error if the cluster is invalid, the token is missing or blank,
or the local TLS files cannot be loaded.

### watch_device

Watches each node using its named, approved device key and the shared token.
Restart the watcher to reload keys or approvals. Leaves agents running.

#### Errors
Returns an error if the cluster, peer names, saved keys, or token are invalid.

### watch_clients

Checks matching nodes and clients in batches of up to four.

### check_node

Checks one agent and prints its counts or an error.

### ClusterSpec::validate

Checks that the cluster has nodes with names and usable IP addresses and ports.

This does not contact agents or check their certificates.

#### Errors
Returns a message if the cluster is empty, a name is blank, or an address
is invalid, has port zero, or uses a wildcard IP.

### ClusterSpec::device_clients

Loads one client per node, in manifest order, using each node's approved peer.

#### Errors
Returns an error if validation, peer lookup, key loading, or token loading fails.

## src/dashboard.rs

### Module overview

Shows live agent status and sends scale commands from a terminal table.

### run

Shows configured nodes while collecting their status in the background.
Up/Down selects a node; = or + adds a copy, and - or Ctrl-minus removes one (0 to 32).
Only one scale command can be pending. Command results appear below the table.
Scaling changes the agent's in-memory target, not its manifest file.
q, Esc, or Ctrl+C closes the screen and restores the terminal.
Rows show the latest reply or connection error, not application health.
Checks run one at a time, with a two-second pause after each round.
Credentials are loaded once. Quitting waits for the current check or pause
and leaves agents running.

#### Errors
Returns an error if credentials cannot be loaded or terminal I/O fails.

#### Panics
Panics if Ratatui cannot set up the terminal. Run in an interactive terminal.

### run_device

Shows and scales agents using each node's named, approved device key.
Uses the same controls as certificate mode. Quitting leaves agents running.

#### Errors
Returns an error if the cluster, credentials, or terminal I/O are invalid.

#### Panics
Panics if Ratatui cannot set up the terminal. Run in an interactive terminal.

### run_clients

Runs the shared screen with one prepared client per node, in manifest order.

### poll_nodes

Checks each node and sends its index and latest result to the screen.
Stops when requested or when the screen's receiver is dropped.

### scale_worker

Receives scale commands and sends their replies back without printing.

### apply_poll

Ignores checks started before the last scale reply or while scaling this node.

### scale_key

Legacy terminals report Ctrl-minus as Ctrl+7 or Ctrl+_.

### scale_command

Builds a scale request from the selected node's latest target, not its running count.

### draw

Draws each node's latest state, hiding addresses on narrow terminals.
Long messages are clipped to the available column width.

#### Panics
Panics if there is no state entry for a configured node.

### NodeState

The latest result of checking an agent, not the health of its application.

### NodeState::NotChecked

No check has finished for this node yet.

### NodeState::Connected

The agent replied with its process counts.

### NodeState::Unreachable

The check failed, including connection, TLS, or authentication errors.

### ScaleCommand

The selected node and its requested target count.

### ScaleResult

A scale reply and its completion time, used to discard older checks.

### PollResult

A timed check lets the screen discard replies made stale by a scale command.

### ShutdownFlag

Stops workers even if setting up or drawing the terminal panics.

## src/device_tls.rs

### Module overview

Creates TLS 1.3 configs that verify both devices using approved public keys.
Used by device-key agent, control, watch, and dashboard commands.
All commands still require a shared token; peer approvals are loaded at setup.

### local_key

Bundles our public key and signer without generating a certificate.
The certificate-shaped container holds raw public-key DER bytes, not X.509.

#### Errors
Returns an error if the signer cannot be loaded or has no public key.

### PinnedServerVerifier

Verifies one approved P-256 server key and its TLS 1.3 handshake signature.
Identifies the server by its pinned key, not a certificate hostname or expiry.
Does not authenticate clients or load the approved peer list itself.

### PinnedServerVerifier::new

Copies the expected key from a peer selected from the approved list.
The caller must select the intended server, not an arbitrary approved peer.

#### Errors
Returns an error for malformed, private, or unsupported keys.

### PinnedServerVerifier::check_key

Rejects any presented key whose full DER bytes differ from the approved key.

### PinnedServerVerifier::verify_server_cert

Approves the pinned raw key and rejects extra certificate-chain entries.
Rustls checks proof of private-key ownership in the signature callback.

### PinnedServerVerifier::verify_tls13_signature

Checks the pinned key, then delegates handshake signature checking to Rustls.

### PinnedServerVerifier::verify_tls12_signature

Rejects TLS 1.2. Device-key configurations must also require TLS 1.3.

### PinnedServerVerifier::supported_verify_schemes

Advertises the P-256/SHA-256 signature scheme used by device identities.

### PinnedServerVerifier::requires_raw_public_keys

Requests raw public keys rather than X.509 certificates.

### TrustedClientVerifier::new

Copies the approved client keys. Rebuild after changing the peer list.

#### Errors
Returns an error if the list is empty or a key cannot be parsed.

### TrustedClientVerifier::check_key

Rejects keys that are not in the copied approval list.

### TrustedClientVerifier::verify_client_cert

Requires one approved raw key, without a certificate chain.

### TrustedClientVerifier::verify_tls13_signature

Checks that the client owns the private key for its approved public key.

### TrustedClientVerifier::verify_tls12_signature

Rejects TLS 1.2. Device-key configurations must also require TLS 1.3.

### TrustedClientVerifier::supported_verify_schemes

Advertises the P-256/SHA-256 signature scheme used by device identities.

### TrustedClientVerifier::requires_raw_public_keys

Requests raw public keys rather than X.509 certificates.

### TrustedClientVerifier

Requires clients to prove ownership of a key in the supplied approval list.
Approvals are copied at setup; changing the store does not update this verifier.

### server_config

Presents our device key and requires an approved client key using TLS 1.3.
Rebuild after changing approvals. Existing connections are not revoked.

#### Errors
Returns an error if the keys or TLS configuration cannot be loaded.

### client_config

Presents our device key and accepts only the selected server's key using TLS 1.3.
The caller must select the intended peer from its approved list.

#### Errors
Returns an error if the keys or TLS configuration cannot be loaded.

## src/identity.rs

### Module overview

Stores device identities, fingerprints public keys, and prepares Rustls signers.
Network authentication does not use these identities yet.

### DeviceIdentity

Holds a device's signing keys. Never print or share the private key.

### DeviceIdentity::generate

Generates an unsaved identity, returning any key-generation error.

### DeviceIdentity::public_key_pem

Returns only the public key as readable PEM text.

### DeviceIdentity::load

Loads a private key, rejecting unsafe files, invalid keys, or read errors.

### DeviceIdentity::save_new

Saves a complete key without overwriting. Requires a private parent directory.
Returns file, permission, or sync errors.

### DeviceIdentity::load_or_create

Reuses a saved key or creates a missing one. Other errors are returned unchanged.

### DeviceIdentity::load_default

Creates private storage in ~/.config/fleet/identity and reuses its key.
Stores device-key.pem and never prints the private key.
Returns storage errors; non-Unix platforms are not supported yet.

### DeviceIdentity::signing_key

Loads this identity into Rustls's signer without changing the saved key.
Does not open a connection or approve any peer.

#### Errors
Returns an error if Rustls cannot load the private key.

### fingerprint

Returns SHA256: followed by 64 lowercase hexadecimal characters for a P-256 key.
Hashes standard DER bytes so PEM whitespace and line endings do not matter.
Compare the full value through a trusted channel; it does not prove ownership.

#### Errors
Returns an error for invalid PEM, private keys, or unsupported key types.

### default_directory

Finds and prepares private storage without creating a device key.
Returns storage errors; non-Unix platforms are not supported yet.

### prepare_directory

Creates or checks private storage without creating a device key.

### check_directory

Rejects symlinks and directories that another user could change.

### write_private

Writes a complete, owner-only file in a private directory.
Existing files must be safe text files no larger than 1 MiB to be replaced.

### read_private

Reads bounded text from a regular, owner-only file in a private directory.

### lock_private

Locks a separate private file until the returned handle is dropped.
Keep the lock file in place so all callers lock the same file.

### ensure_directory

New directories are private; existing unsafe directories are rejected, not modified.

## src/protocol.rs

### Module overview

Shared types for JSON messages between the client and agent.

Requests include a shared token. Each message ends with a newline.
Messages are carried over mutual TLS, which encrypts the token and commands.

### StatusResponse

The agent's status, sent as JSON on one line.

### StatusResponse::workload_name

The managed workload's name, or `None` when there is no workload.

### StatusResponse::desired

The requested number of running copies.

### StatusResponse::running

The number of copies observed running.

### Request

A client command carried inside an authenticated request.

### Request::Status

Ask for the current workload and counts.

### Request::Stop

Set the target to zero and stop all copies.

### Request::Scale

Change the target; the agent adjusts processes on its next loop.

### Response

An agent reply: current status or a reason the request was rejected.

### Response::Status

The workload and current counts.

### Response::Error

A readable error message.

### AuthenticatedRequest

A command and the shared token needed to run it.

Debug printing is not derived to avoid accidentally logging the token.

### AuthenticatedRequest::token

The secret read from `FLEET_TOKEN`. Do not log it.

### AuthenticatedRequest::request

The command to handle after checking the token.

## src/runner.rs

### Module overview

Launches local processes and checks whether they are still running.

### ProcessRunner

Stores handles to processes launched by Fleet.

Finished handles are removed when `running_count` checks the list.

### ProcessRunner::children

Handles used to inspect the launched processes.

### ProcessRunner::new

Creates an empty runner without starting any processes.

### ProcessRunner::start

Starts one copy of the workload and stores its process handle.
The child does not inherit Fleet's control token.

#### Errors
Returns an error if the program cannot be launched.

### ProcessRunner::running_count

Checks processes without waiting and removes handles for exited processes.

Returns the number of handles whose processes were observed still running.

#### Panics
Panics if a process status check fails.

### ProcessRunner::stop_one

Force-stops one tracked process and collects its exit status.
Does nothing when no handles remain.

#### Panics
Panics if stopping or waiting for the process fails.

## src/tls.rs

### Module overview

Loads certificates and opens encrypted connections with a fixed deadline.

### CONNECTION_TIMEOUT

Maximum socket I/O time for the handshake, command, and reply together.

### MAX_MESSAGE_BYTES

Maximum message size, including its final newline.

### TlsFiles

Paths to trusted CA certificates, our certificate, and our private key.

### TlsFiles::ca_cert

CA certificates trusted to sign the other side's identity.

### TlsFiles::cert

Our certificate chain in PEM format.

### TlsFiles::private_key

Our private key in PEM format. Keep this file private.

### load_certificates

Loads certificates, returning an error for unreadable or empty files.
Loading does not establish trust; TLS verifies the peer later.

### load_private_key

Loads the first private key, rejecting missing keys or broad Unix permissions.

### load_roots

Loads trusted CA certificates, rejecting invalid certificates.

### server_config

Requires a trusted client certificate and supplies the agent's identity.
Every accepted client still needs the shared token to run commands.

### client_config

Verifies the agent's certificate and supplies the client's identity.

### ServerStream

An agent-side TLS connection with bounded socket I/O.

### ClientStream

A client-side TLS connection with bounded socket I/O.

### accept

Completes client authentication before any command is read.

### connect

Connects to a numeric IP and verifies the expected server name.
Uses an already-loaded config and opens a new connection with a fixed deadline.

#### Errors
Returns an error if the address or server name is invalid, connecting fails,
or the TLS handshake fails.

### read_message

Reads one newline-terminated message without allowing unlimited allocation.
Returns an error for oversized, incomplete, or invalid UTF-8 messages.

### DeadlineStream

Limits socket I/O to one deadline across the handshake, command, and reply.

## src/trust.rs

### Module overview

A device label and its public key, never its private key.

### TrustedPeer::name

A validated P-256 public key in a consistent PEM format.

Stores peers without duplicate names or public keys.

### normalize_public_key

### read_public_key
